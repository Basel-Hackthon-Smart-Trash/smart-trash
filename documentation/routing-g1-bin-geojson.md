## Contracts And Policy

`smart_bin_routing.adapters.bin_geojson.load_bin_geojson(path)` is the public
adapter entry point. It returns `tuple[BinMetadata, ...]`; the optimizer and
its matrix contract do not see GeoJSON objects.

- `feature.id` is the canonical `bin_id`; row order is never used as identity.
- `properties["@id"]` is retained as `source_id` and must match `feature.id`.
- Coordinates are retained unchanged in `BinMetadata.location` as the original
  position. No snapped network position exists in this session.
- CRS-omitted GeoJSON is accepted under RFC 7946 WGS84 longitude/latitude
  semantics. Any explicit CRS is rejected because no transformation is
  supported.
- Provenance records format, caller-supplied source path, and optional generator.
- No readings, demand, weights, service times, routes, or geographic-derived
  operational values are created.
- Output is sorted by stable `bin_id`, making mappings independent of feature
  order.

The adapter rejects missing or mismatched identities, duplicate IDs, non-Point
geometry, missing/non-finite/out-of-range coordinates, malformed properties,
and unsupported CRS declarations.
